# FleetGuard — نظام فحص وإدارة الأسطول

تم استخدام شعار الغالبي الأصلي وألوان الكحلي والأزرق ونموذج الشركة. يحتوي النموذج على **32 صفًا مرقمًا: 27 بند فحص، واسم السائق، وإقراره، وتاريخ انتهاء رخصته، واعتماد المشرف، وسجل الأعطال والإجراء المتخذ**. لا تُعامل حقول الاعتماد كبنود ناجح أو راسب.

**الحالة: الكود وبناء الواجهة واختبارات قاعدة البيانات المحلية جاهزة للمراجعة؛ لم يُعتمد النظام للإنتاج.** يجب إعداد مشروع Supabase ثم اختبار المصادقة الحية والبريد ورفع الصور والأجهزة المحمولة والنشر. لا توجد حسابات تشغيل تجريبية أو كلمات مرور افتراضية.

## التشغيل والإعداد

1. ثبّت Node.js 22 أو 24 ونفّذ `npm ci`.
2. انسخ `.env.example` إلى `.env` وضع عنوان Supabase والمفتاح العام فقط. للتشغيل المحلي استخدم `VITE_BASE_PATH=/`.
3. اربط مشروع Supabase باستخدام `supabase link --project-ref YOUR_PROJECT_REF` ثم `supabase db push`.
4. عطّل التسجيل العام في إعدادات Authentication، واضبط طول كلمة المرور على 12 على الأقل، وأعدّ بريد SMTP لدعوات الموظفين واستعادة كلمات المرور.
5. اضبط عنوان الموقع وروابط إعادة التوجيه المسموح بها على رابط الواجهة الفعلي، متضمنًا مسار المستودع والشرطة النهائية `/`.
6. اضبط `APP_ORIGIN` و`APP_URL` كإعدادات لدالة Supabase ثم نفّذ `supabase functions deploy gateway --no-verify-jwt`. تتحقق الدالة بنفسها من JWT وصلاحية المدير في كل عملية إدارية.
7. لإنشاء أول مدير، استخدم `npm run bootstrap` من جهاز موثوق مع متغيرات البيئة الخاصة الموضحة في README. يرسل الأمر دعوة خاصة للمدير ليحدد كلمة مروره. لا يوجد رابط عام لإنشاء المدير ولا كلمة مرور مشتركة.
8. ادخل برقم الموظف، وادعُ المشرف ثم السائق، وأضف المركبات والتعيينات اليومية. يجب إجراء فحص حقيقي ومراجعته قبل اعتماد التشغيل.

**لا ترسل المفتاح السري service-role في المحادثة، ولا تضعه في GitHub أو أي متغير يبدأ بـ VITE_.** تستعمل الواجهة المفتاح العام وJWT المستخدم، وتُفرض الصلاحيات داخل PostgreSQL عبر RLS والدوال المتحققة. تعطيل الموظف يمنع وصوله إلى البيانات حتى لو بقي رمز الجلسة لديه.

## الوظائف

- واجهة عربية RTL وإنجليزية LTR فقط، مع حفظ تفضيل اللغة في حساب الموظف.
- دعوات حسابات مستقلة، أدوار مدير ومشرف وسائق، تعديل الموظفين وتعطيلهم وإعادة تعيين كلمات المرور.
- إدارة المركبات والتعيينات اليومية، ورمز QR فريد لكل مركبة. الرمز لا يتجاوز المصادقة أو التعيين.
- فحص بلا نتائج محددة مسبقًا، مع سبب إلزامي للعطل وغير المنطبق، وصور خاصة، وإقرار السائق ووقت إرسال من الخادم.
- اعتماد أو رفض المشرف، وسجل أعطال تلقائي، وإجراءات صيانة مدققة، وتقارير لا يمكن تعديل إجاباتها بعد الإرسال.
- إحصاءات من قاعدة البيانات، وفلاتر، وتصدير XLSX، وطباعة PDF من المتصفح مع دعم العربية.

## النشر والاختبارات

دليل [README.md](README.md) يشرح إعداد Supabase وGitHub Pages بالتفصيل. ضع عنوان المشروع والمفتاح العام في Repository Variables ثم فعّل Pages باستخدام GitHub Actions. لا يتطلب بناء الواجهة أي مفتاح إداري.

نفّذ `npm test` و`npm run build` وراجع [نتائج التحقق](docs/VALIDATION.md) و[قائمة ما قبل الإنتاج](docs/DEPLOYMENT.md).

المسودات غير المرسلة تبقى إجاباتها في الصفحة الحالية فقط؛ العمل دون إنترنت والمزامنة غير منفذين. التصدير العام يشمل السجلات المحملة حتى 1000 سجل، مع إمكانية فلترة التاريخ من الخادم؛ تصدير التقرير الفردي يشمل جميع إجاباته. الإقرار المكتوب ليس توقيعًا إلكترونيًا معتمدًا قانونيًا، واكتمال الفحص لا يمنح تصريح تشغيل. يجب اعتماد سياسة الأعطال الحرجة ومعنى PA والاحتفاظ بالسجلات من الشركة.
